# StockMind
StockMind — персональная аналитическая платформа для работы с акциями и другими финансовыми активами. Она объединяет графики, рыночные показатели, инструменты технического анализа, сравнение активов, оценку рисков, новости и управление инвестиционным портфелем в едином рабочем пространстве.



# МЕТОДИЧЕСКОЕ ОБЕСПЕЧЕНИЕ ПРОЕКТА STOCKMIND

## 1. Общие положения

Настоящее методическое обеспечение определяет основные принципы, методы и порядок разработки программного проекта StockMind, а также обосновывает выбор подходов к реализации его функциональных возможностей.

StockMind представляет собой аналитическую систему, предназначенную для сбора, обработки, систематизации и анализа информации о финансовых инструментах. Основное назначение проекта заключается в решении проблемы недостаточной структурированности информации, с которой сталкивается пользователь при анализе рынка. Система должна предоставлять инструменты для просмотра рыночных данных, изучения динамики стоимости активов, сравнения финансовых инструментов и оценки связанных с ними рисков.

Документ предназначен для участников команды разработки, лиц, осуществляющих проверку проекта, а также пользователей, которым необходимо ознакомиться с принципами функционирования и развития системы.

Методическое обеспечение составлено с учетом первоначальных материалов проекта, концепции StockMind и доступных сведений о работе с данными Московской биржи.

## 2. Цель и задачи проекта

### 2.1. Цель проекта

Целью разработки StockMind является создание программного средства, упрощающего процесс анализа финансовых инструментов за счет объединения рыночной информации и аналитических инструментов в единой системе.

Проект направлен на сокращение времени, затрачиваемого пользователем на поиск и сопоставление информации, повышение удобства работы с рыночными данными и предоставление инструментов для более последовательного анализа финансовых активов.

### 2.2. Задачи проекта

Для достижения поставленной цели предусматривается решение следующих задач:

1. Изучение предметной области и определение потребностей потенциальных пользователей.
2. Анализ доступных источников информации о финансовых инструментах.
3. Разработка механизма получения и обработки рыночных данных.
4. Организация хранения и представления полученной информации.
5. Реализация инструментов просмотра динамики стоимости финансовых активов.
6. Разработка средств сравнения финансовых инструментов.
7. Проработка методов технического анализа и оценки рисков.
8. Разработка пользовательского интерфейса.
9. Проверка корректности работы реализованных модулей.
10. Подготовка программной и методической документации.

## 3. Основные функциональные и нефункциональные требования

### 3.1. Функциональные требования

Разрабатываемая система должна предусматривать следующие функциональные возможности:

- получение информации о финансовых инструментах из доступных источников;
- отображение основных сведений об активах;
- просмотр исторических данных и динамики изменения стоимости;
- представление рыночной информации в графическом виде;
- сравнение нескольких финансовых инструментов;
- применение аналитических методов для изучения рыночной динамики;
- предоставление пользователю структурированной информации для самостоятельного анализа.

В соответствии с дальнейшим развитием концепции также рассматриваются следующие возможности:

- создание и ведение пользовательских списков наблюдения;
- формирование аналитического портфеля;
- подготовка аналитических отчетов;
- применение интеллектуального помощника для работы с информацией;
- расширение перечня источников рыночных данных.

Перечисленные дополнительные возможности относятся к направлениям развития проекта и не должны рассматриваться как реализованные до подтверждения их наличия в программном продукте.

### 3.2. Нефункциональные требования

К системе предъявляются следующие нефункциональные требования:

- **Удобство использования.** Интерфейс должен обеспечивать понятное взаимодействие с основными функциями программы.
- **Надежность.** Ошибки получения или обработки данных не должны приводить к некорректному отображению остальной информации.
- **Производительность.** Основные операции просмотра и обработки данных должны выполняться за приемлемое время.
- **Расширяемость.** Архитектура должна допускать добавление новых аналитических модулей и источников данных.
- **Сопровождаемость.** Программный код должен иметь понятную структуру, позволяющую вносить изменения и исправлять ошибки.
- **Корректность данных.** При отображении информации необходимо учитывать источник, период и возможные задержки обновления.

При формировании требований к качеству программного продукта учитываются положения ГОСТ Р ИСО/МЭК 25010-2015, устанавливающего модель оценки качества систем и программного обеспечения [2].

## 4. Применяемые технологии и решения. Обоснование применяемых технологий

### 4.1. Источники рыночных данных

В качестве одного из рассматриваемых источников рыночной информации используется программный интерфейс ISS Московской биржи.

ISS предоставляет доступ к сведениям о финансовых инструментах, котировкам, сделкам, историческим данным и информации, необходимой для построения графиков. Взаимодействие с интерфейсом осуществляется по протоколу HTTP [1].

Применение данного источника обосновано следующими факторами:

- наличие информации непосредственно от организатора торгов;
- возможность получения исторических рыночных данных;
- наличие сведений о финансовых инструментах и параметрах торгов;
- возможность интеграции с клиентскими программными приложениями;
- наличие официальной документации по интерфейсу.

Использование ISS соответствует задаче получения рыночной информации для последующего отображения и анализа. При этом необходимо учитывать условия предоставления данных, в том числе возможные задержки и ограничения доступа.

### 4.3. Обоснование выбора решений

Использование MOEX ISS обусловлено необходимостью получать рыночную информацию из специализированного источника. Применение официального интерфейса позволяет снизить зависимость от сторонних агрегаторов и использовать структурированные данные, предназначенные для обработки программными средствами.

Применение Git и GitHub обосновано необходимостью сохранять историю разработки, отслеживать изменения и обеспечивать совместную работу участников команды. Система контроля версий позволяет определить, какие изменения были внесены, когда они были выполнены и каким участником [6].

Окончательное обоснование выбора языка программирования, библиотек, фреймворков, СУБД и средств автоматизации должно быть дополнено после проверки фактической структуры проекта. При разработке StockMind рассматриваются альтернативные подходы к получению рыночных данных, организации приложения и представлению аналитической информации.

### 5.1. Альтернативы получения рыночных данных

| Критерий | MOEX ISS API | Сторонние агрегаторы данных |
|---|---|---|
| Источник информации | Инфраструктура Московской биржи | Внешние поставщики данных |
| Доступность исторических данных | Предусмотрена интерфейсом | Зависит от поставщика |
| Специализация на российском рынке | Высокая | Зависит от сервиса |

Для работы с инструментами Московской биржи целесообразно использовать MOEX ISS API, поскольку он предоставляет сведения непосредственно из инфраструктуры биржи. Сторонние агрегаторы могут рассматриваться как дополнительные источники в случае расширения проекта на другие рынки или необходимости получения дополнительных типов информации.

Выбранный подход позволяет сосредоточить первоначальную реализацию на российском фондовом рынке и уменьшить количество внешних зависимостей.

| Критерий | Настольное приложение | Веб-приложение |

В первоначальной версии StockMind рассматривается настольный формат приложения. Такой подход позволяет сосредоточить разработку на локальном пользовательском интерфейсе и аналитических функциях.

Веб-архитектура является возможной альтернативой для дальнейшего развития проекта. Она может упростить централизованное обновление и доступ с различных устройств, однако потребует отдельной проработки серверной части, размещения и вопросов информационной безопасности.

Изменение плана реализации предусматривает сохранение первоначального настольного формата на текущем этапе и рассмотрение веб-версии в качестве перспективного направления, если возникнет необходимость расширить способы доступа к системе.

## 6. Методика разработки и организация командной работы

Разработка StockMind осуществляется поэтапно. Каждый этап предполагает выполнение определенного набора задач, проверку полученных результатов и фиксацию изменений в проекте.

### 6.1. Основные этапы разработки

**Этап 1. Анализ требований**

На данном этапе определяются назначение системы, основные пользовательские задачи, функциональные и нефункциональные требования. Формируется перечень возможностей, которые должны быть реализованы в первую очередь.

**Этап 2. Проектирование**

Разрабатывается общая структура приложения, определяются основные программные компоненты, способы взаимодействия между ними и порядок получения рыночных данных.

**Этап 3. Реализация**

Выполняется программирование основных модулей, создание пользовательских экранов и подключение источников информации.

**Этап 4. Тестирование**

Проверяется корректность получения, обработки и отображения информации. Выявляются ошибки и выполняются необходимые исправления.

**Этап 5. Документирование**

Подготавливаются описание системы, инструкции по использованию, сведения о применяемых технологиях и материалы, необходимые для сопровождения проекта.

### 6.2. Организация совместной работы

Для хранения исходного кода и контроля изменений используется репозиторий GitHub.

Репозиторий проекта:

В процессе командной разработки рекомендуется использовать следующий порядок работы:

1. Участники команды получают доступ к репозиторию.
2. Каждый участник выполняет закрепленные за ним задачи.

6. История коммитов используется для анализа хода разработки и определения вклада участников.

История изменений должна отражать фактическую работу команды. Коммиты должны содержать осмысленные сообщения, а авторство изменений должно соответствовать реальным участникам разработки.

Наличие ссылки на репозиторий само по себе не подтверждает выполнение требования о командной работе. Для подтверждения необходимо проверить наличие исходных файлов, промежуточных результатов, истории коммитов и изменений от нескольких участников.

## 7. Архитектура и основные компоненты системы

В соответствии с назначением проекта архитектура StockMind должна обеспечивать получение рыночных данных, их обработку и последующее представление пользователю.

В общем виде работа системы может быть представлена следующей последовательностью:

1. Пользователь выбирает финансовый инструмент или запрашивает необходимую информацию.
2. Программный компонент получает соответствующие данные из источника.
3. Полученная информация проходит обработку и проверку.
4. Подготовленные данные передаются компонентам отображения.
5. Пользователь изучает результаты и выполняет аналитические действия.

Основные логические компоненты системы:

- **Компонент получения данных** — отвечает за взаимодействие с внешними источниками рыночной информации.
- **Компонент обработки данных** — выполняет подготовку полученной информации для дальнейшего использования.
- **Аналитический компонент** — предназначен для выполнения расчетов и анализа динамики финансовых инструментов.
- **Компонент визуализации** — обеспечивает представление данных в виде таблиц, графиков и других элементов интерфейса.
- **Пользовательский интерфейс** — обеспечивает взаимодействие пользователя с функциональными возможностями системы.

Приведенное описание отражает логическое разделение функций. Фактическое распределение компонентов по файлам, классам и программным модулям определяется структурой исходного кода.

## 8. Порядок проверки и тестирования

Тестирование StockMind необходимо для подтверждения корректности работы основных функций и соответствия программного продукта установленным требованиям.

### 8.1. Проверка получения данных

Проверяется:

- возможность обращения к источнику рыночной информации;
- корректность обработки ответа;
- наличие необходимых полей;
- обработка ситуаций, когда источник временно недоступен;
- корректность отображения даты и времени получения данных.

### 8.2. Проверка обработки данных

Проверяется:

- правильность преобразования полученной информации;
- отсутствие необоснованного изменения числовых значений;
- корректность обработки пустых или неполных данных;
- соответствие результатов расчетов исходным значениям.

### 8.3. Проверка пользовательского интерфейса

Проверяется:

- доступность основных элементов управления;
- корректность отображения информации;
- соответствие подписей и значений;
- обработка действий пользователя;
- понятность сообщений об ошибках.

### 8.4. Проверка качества

При оценке качества программного продукта учитываются функциональная пригодность, производительность, удобство использования, надежность и сопровождаемость. Данные характеристики согласуются с моделью качества, представленной в ГОСТ Р ИСО/МЭК 25010-2015 [2].

Конкретные результаты тестирования должны фиксироваться по фактически выполненным проверкам. Нельзя указывать успешное прохождение тестов без соответствующих результатов.

## 9. Работа с рыночной информацией и ограничения анализа

StockMind предназначен для информационной и аналитической поддержки пользователя. Полученные данные могут использоваться для изучения динамики финансовых инструментов, сравнения активов и оценки рыночных тенденций.

При работе с информацией необходимо учитывать следующие обстоятельства:

- данные могут поступать с задержкой;
- доступность отдельных сведений зависит от источника;
- историческая динамика не гарантирует аналогичного поведения актива в будущем;
- аналитические показатели не являются гарантией результата;
- технические индикаторы и графические модели не позволяют достоверно предсказывать все изменения рынка.

Результаты анализа StockMind следует рассматривать как информационный материал для самостоятельного изучения. Система не гарантирует получение прибыли и не должна восприниматься как замена профессиональной финансовой консультации.
